## The configuration is the game

The configuration is one JSON file — `data/data.json` by default. Here is a scene with a
single actor in it, abridged, to show the shape of what the editor produces:

```json
{
  "startSceneId": "b8f1…",
  "scenes": [
    {
      "id": "b8f1…",
      "name": "island-level",
      "actors": [
        {
          "id": "4",
          "name": "background",
          "children": [],
          "components": [
            {
              "name": "Transform",
              "config": {
                "offset": { "x": 0, "y": 0 },
                "rotation": 0,
                "scale": { "x": 1, "y": 1 }
              }
            },
            {
              "name": "Sprite",
              "config": {
                "src": "grass-tile.png",
                "width": 320,
                "height": 320,
                "fit": "repeat",
                "sortingLayer": "background"
              }
            }
          ]
        }
      ]
    }
  ],
  "systems": [
    { "name": "CameraSystem", "options": { "windowNodeId": "root" } },
    {
      "name": "Renderer",
      "options": { "windowNodeId": "root", "backgroundColor": "#000" }
    }
  ]
}
```

Notice there is no logic anywhere: the file says what exists, never what happens.

## Your game builds the engine

The logic lives in your code. You hand the engine the classes the configuration draws on,
and it builds the world:

```ts
import {
  Engine,
  Renderer,
  CameraSystem,
  Transform,
  Sprite,
  Texture,
} from 'dacha';

import config from '../data/data.json';

const engine = new Engine({
  config,
  systems: [Renderer, CameraSystem],
  components: [Transform, Sprite],
  assets: [Texture],
});

void engine.play();
```

That is the whole shape of an entry point. The generated project's version lists a few
more built-ins than this, and nothing else. `config` is imported like any other module, so
a save in the editor reaches the running game through your dev server.

## Inside a frame

Once the world is built, the loop takes over. It runs on `requestAnimationFrame` and calls
systems in two separate phases.

<FrameDiagram />

**`update`** runs once per rendered frame and receives a variable time delta.
**`fixedUpdate`** runs on its own clock, at a rate that does not follow the frame rate, so
that a game behaves the same on a 60 Hz laptop and a 144 Hz monitor. When you write a
system you choose the phase.

## The editor reads the same project

The editor learns about your components and systems by scanning your source for files
matching a set of patterns, importing them, and letting the decorators on each class
register it along with the fields the inspector should draw. It reads your assets directory
the same way.
